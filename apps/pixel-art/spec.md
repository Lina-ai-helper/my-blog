> 상태: **Plan 단계 산출물**. 이 문서는 계획서이며, 이 시점까지 구현 코드는 작성하지 않았다.
> 저장소 루트 `CLAUDE.md`의 기술 원칙(프레임워크/외부 라이브러리 금지, 빌드 도구 없음, 모던 표준 사용)을
> 그대로 따르되, 이 앱은 블로그 본체와 분리된 독립 미니앱으로 `apps/pixel-art/` 안에 자체 완결된다.
> 형식과 수준감은 `apps/2048/spec.md`를 참고했다.

## 1. 앱 개요 및 주요 기능

16x16 격자에 마우스 클릭/드래그 또는 모바일 터치로 도트를 찍어 그림을 그리고, 완성한 그림을 PNG 파일로
저장할 수 있는 픽셀 아트 에디터. 순수 HTML/CSS/JS(Vanilla, ES Modules)로 구현하고 외부 라이브러리는
쓰지 않는다.

주요 기능 목록:

- 16x16 격자 캔버스 렌더링 (Canvas API 사용, 셀 단위로 색을 칠함)
- 클릭 한 번으로 한 칸 칠하기 + 드래그로 여러 칸 연속 칠하기 (마우스)
- 터치 드래그로 여러 칸 연속 칠하기 (모바일)
- 색상 팔레트: 미리 정의된 프리셋 색상 12~16개 중 선택
- 커스텀 색상 선택: 네이티브 `<input type="color">`로 임의의 색을 골라 팔레트에 즉시 반영
- 지우개 도구: 선택 시 칠하는 대신 해당 칸을 투명(빈 칸)으로 되돌림
- 전체 지우기(clear): 확인 후 격자 전체를 초기 상태(빈 칸)로 리셋
- PNG로 저장(다운로드): 현재 그림을 `.png` 파일로 다운로드 (배경은 기본적으로 투명)
- 실행 취소(undo): 스트로크(펜을 대고 뗄 때까지) 단위로 최근 변경을 되돌리는 기능. 아래 이유로
  **이번 계획의 범위에 포함한다**: 16x16 격자 전체 상태는 매우 작아(최대 256칸) 스냅샷 저장 비용이
  거의 없고, 그림 그리기 도구에서 실수를 되돌리는 기능은 사용성에 크게 기여하기 때문이다. 다만 구현은
  "스트로크 단위 스냅샷 스택(깊이 제한 있음)"이라는 가장 단순한 방식으로 한정한다(칸 단위 세밀한
  undo, redo, 다중 undo 트리 등은 비범위).
- 반응형 레이아웃 (모바일 우선, 가로 스크롤 없음), 라이트/다크 모드는 블로그 본체와 무관한 별도 앱이므로
  이번 범위에서는 다루지 않는다(2048 앱과 동일한 판단).

범위에서 제외하는 것(비범위):
- 실행 취소 이후의 "다시 실행(redo)"
- 칸 단위(픽셀 단위) 세밀한 undo 히스토리, 무제한 undo
- 그림 불러오기(파일 업로드로 기존 이미지 가져오기), 레이어, 브러시 크기 조절, 도형 도구(선/사각형/채우기)
- 격자 크기 변경(항상 16x16 고정), 여러 그림 저장/갤러리, `localStorage`를 통한 작업 중 그림 자동 저장
  (새로고침하면 그림은 사라짐 — 필요성이 제기되면 후속 계획에서 다룬다)
- 온스크린 키보드로 캔버스를 완전히 대체하는 그리기(6장에서 대안으로 간단히 다룸)

## 2. 파일 구조

```
apps/pixel-art/
├── index.html     # 페이지 뼈대: 헤더(제목), 캔버스 컨테이너, 팔레트 영역, 툴바(지우개/전체지우기/undo/저장), 상태 안내 영역
├── style.css      # 이 앱 전용 스타일 (자체 CSS 변수 팔레트, 반응형 레이아웃, 격자/스와치/버튼 스타일)
├── editor.js      # 진입점(ES Module): 각 모듈을 조립하고 이벤트를 배선(오케스트레이션), 렌더링 트리거
├── grid.js        # 격자 상태 표현과 순수 로직(DOM 비의존): 셀 읽기/쓰기, 전체 지우기, 스냅샷 생성/복원
├── canvas.js       # Canvas 렌더링 전담: 격자 상태 → 화면에 그리기, PNG 내보내기용 렌더링
├── palette.js      # 팔레트 상태 관리: 프리셋 색상 목록, 현재 선택 색상, 지우개 모드, 커스텀 색상 연동
├── pointer.js      # 마우스/터치 드로잉 입력 통합 처리 (Pointer Events 기반), 좌표 → 셀 인덱스 변환
└── spec.md         # 이 계획 문서
```

파일을 이렇게 나누는 이유: `grid.js`는 DOM에 의존하지 않는 순수 상태/로직(2048의 `board.js`와 같은 역할)
으로 분리해 테스트하기 쉽게 하고, `canvas.js`는 "상태 → 화면/PNG" 변환만 전담해 렌더링 관심사를 한 곳에
모은다. `palette.js`는 색상/도구 선택 상태를, `pointer.js`는 입력 이벤트 처리(좌표 계산·드래그 감지)를
전담해 "함수는 작고 한 가지 일만" 원칙을 지킨다. `editor.js`는 이 모듈들을 연결하는 얇은 오케스트레이션
계층으로만 유지한다.

## 3. 핵심 로직 설계 요약

### 격자/픽셀 상태 표현
- 16x16 색상 배열을 길이 256의 1차원 배열(`(string|null)[256]`)로 표현한다. 인덱스는
  `index = y * 16 + x`로 계산한다(1차원이 스냅샷 복제·순회에 더 단순하고 가볍기 때문에 2048의
  2차원 배열 방식과 달리 이 앱은 1차원을 택한다).
- 빈 칸(아직 칠하지 않은 칸)은 `null`로 표기하며, 렌더링/PNG 저장 시 투명 픽셀로 취급한다. 칠해진 칸은
  `'#rrggbb'` 형태의 문자열을 저장한다.
- 상태 객체 예시(설명용, 실제 타입은 구현 시 확정):
  `{ cells: (string|null)[256], size: 16 }`
- `grid.js`는 `getCell(state, x, y)`, `setCell(state, x, y, colorOrNull)`, `clearAll(state)`,
  `cloneCells(state)`(undo 스냅샷용) 같은 작은 순수 함수로 구성한다.

### 그리기 이벤트 처리 (마우스/터치 드래그 공통화)
- **Pointer Events**(`pointerdown`/`pointermove`/`pointerup`/`pointercancel`)를 사용해 마우스와 터치를
  하나의 이벤트 체계로 통합 처리한다. 별도의 `mousedown`/`touchstart` 분기를 두지 않아도 되므로
  "마우스 드래그/터치 드래그 공통화"가 자연스럽게 해결된다(모던 표준을 쓰라는 CLAUDE.md 원칙에도 부합).
- 처리 흐름:
  1. `pointerdown`: 눌린 지점의 셀 좌표를 계산해 칠하기(또는 지우기) 시작. undo용 스냅샷을 이 시점에
     한 번 저장(스트로크 시작 시점의 상태를 보관).
     `canvas.setPointerCapture(e.pointerId)`로 포인터를 캡처해, 손가락/마우스가 캔버스 밖으로 나가도
     같은 스트로크로 계속 추적되게 한다.
  2. `pointermove`: 캡처된 상태에서 이동할 때마다 현재 지점의 셀 좌표를 계산. 이전에 칠한 셀과 다르면
     새 셀을 칠한다(같은 셀 위에서 움직일 때 중복 처리를 피하기 위해 "마지막으로 칠한 셀" 좌표를 기억).
     빠르게 움직여 셀 하나를 건너뛰는 경우를 줄이기 위해, 이전 셀과 현재 셀 사이를 간단한 정수 좌표
     보간(직선 보간)으로 이어 칠한다(브레젠험 알고리즘 수준의 단순 구현으로 충분 — 격자가 16x16으로
     작아 과도한 최적화는 불필요).
  3. `pointerup`/`pointercancel`: 스트로크 종료. 실제로 변경이 있었다면(칠한 칸이 하나 이상) 스트로크
     시작 시점의 스냅샷을 undo 스택에 push한다(변경이 없었다면 스냅샷을 버려 불필요한 undo 항목이
     쌓이지 않게 한다).
  4. 좌표 → 셀 변환: `canvas.getBoundingClientRect()`와 캔버스의 내부 해상도(`canvas.width`/`height`)
     비율을 이용해 CSS로 스케일된 화면 좌표를 16x16 격자 인덱스로 변환한다(반응형으로 캔버스가
     CSS 상에서 확대/축소되어도 정확히 매핑되도록).
  5. 터치에서 페이지 스크롤과 그리기 제스처가 충돌하지 않도록 캔버스에 `touch-action: none`을 지정한다.

### PNG로 저장하는 방법
- **편집용 캔버스**: 16x16 격자를 셀당 32px로 그려 내부 해상도 512x512 `<canvas>`를 사용한다(터치로
  칠하기 편한 크기 확보). `ctx.imageSmoothingEnabled = false`로 두어 칸 경계가 흐려지지 않게 한다.
  작은 화면에서는 CSS로 `width: min(90vw, 512px)` 형태로 줄여 보여주되, `image-rendering: pixelated`를
  함께 지정해 축소 시에도 경계가 흐려지지 않게 한다.
- **격자 구분선**: 칸 사이 얇은 구분선은 캔버스에 직접 그리지 않고, 캔버스를 담는 컨테이너 요소의 CSS
  배경(`repeating-linear-gradient` 등)으로 표현한다. 이렇게 하면 구분선이 실제 픽셀 데이터에 섞이지
  않아, PNG로 저장했을 때 구분선 없이 순수한 그림만 내보낼 수 있다.
- **내보내기(export) 방식**: 저장 시점에 오프스크린 `<canvas>`(화면에 붙이지 않는 임시 캔버스)를
  새로 만들어, `grid.js`의 상태(`cells` 배열)를 기준으로 **픽셀당 정수 배율**(기본값: 16px/칸,
  즉 256x256 PNG)로 다시 그린다. 편집용 캔버스를 그대로 내보내지 않고 별도로 그리는 이유는, 편집
  배율(32px/칸)과 내보내기 배율을 분리해 두면 나중에 "저장 크기 선택" 같은 옵션을 추가하기 쉽고,
  구분선이 실수로 섞여 들어갈 여지도 없기 때문이다. 빈 칸(`null`)은 `fillRect`를 호출하지 않고 그대로
  두어 알파 채널이 투명하게 유지되게 한다(`imageSmoothingEnabled = false`도 동일하게 적용).
- **다운로드 트리거**: 오프스크린 캔버스에서 `canvas.toBlob(blob => { ... }, 'image/png')`를 호출해
  Blob을 얻고, `URL.createObjectURL(blob)`로 임시 URL을 만든 뒤, 보이지 않는 `<a>` 요소의 `href`에
  연결하고 `download` 속성(예: `pixel-art.png`)을 지정해 `a.click()`으로 다운로드를 트리거한다.
  트리거 직후(또는 짧은 지연 후) `URL.revokeObjectURL()`로 메모리를 해제한다(`toDataURL`보다 `toBlob`이
  대용량 데이터를 문자열로 들고 있지 않아 메모리 효율이 더 좋으므로 이 방식을 택한다).

### 팔레트 상태 관리
- `palette.js`가 다음 상태를 관리한다: 프리셋 색상 배열(고정 상수, 12~16개 — 무채색 3~4단계 + 대표
  유채색 8~12개로 구성해 색상환을 고르게 커버), 현재 선택된 색상(`selectedColor: string`), 지우개
  모드 여부(`eraserActive: boolean`), 커스텀 색상 값(`<input type="color">`의 현재 값).
- "현재 칠할 색"은 하나의 파생 값으로 계산한다: 지우개 모드가 켜져 있으면 칠할 값은 `null`(지우기),
  아니면 `selectedColor`. 이렇게 지우개를 "특수한 색상 값"이 아니라 별도의 모드 플래그로 다루면
  `pointer.js`/`canvas.js` 쪽 로직이 단순해진다.
- 팔레트 스와치를 클릭/키보드로 선택하면 `selectedColor`를 갱신하고 동시에 `eraserActive`를 `false`로
  되돌린다(색상 선택 = 지우개 해제). 지우개 버튼을 누르면 `eraserActive`만 `true`로 토글한다.
- 커스텀 색상(`<input type="color">`)에서 값이 바뀌면 `selectedColor`를 그 값으로 갱신하고, 팔레트에는
  "현재 커스텀 색" 스와치 하나를 프리셋 뒤에 추가로 표시해 선택 상태를 시각적으로 알 수 있게 한다.

## 4. UI/디자인 개요

- 이 앱은 블로그 본체와 분리된 독립 미니앱이므로, 블로그의 색 변수 체계를 그대로 따르지 않고
  **자체 CSS 변수 팔레트**를 `apps/pixel-art/style.css`의 `:root`에 정의한다. 다만 CLAUDE.md의 디자인
  원칙(색은 절제해서 사용, 그림자·애니메이션 최소화, 모든 색은 변수로 정의하고 하드코딩 금지)은 그대로
  지킨다. UI 자체(배경, 버튼, 텍스트)는 차분한 중성 톤(예: 옅은 회색 배경 + 짙은 회색 텍스트)으로 두고,
  화려한 색은 그림 그리기 팔레트 스와치에만 등장하게 한다.
- 레이아웃(모바일 우선): 세로로 헤더(제목) → 캔버스(정사각형, 화면 폭에 맞춰 `min(90vw, 512px)`로
  제한) → 팔레트(스와치 그리드 + 커스텀 색상 picker) → 툴바(지우개 토글 / 전체 지우기 / 실행 취소 / PNG
  저장 버튼) 순서로 쌓는다. 화면이 넓어지면(`min-width` 미디어 쿼리) 캔버스를 왼쪽에, 팔레트+툴바를
  오른쪽 세로 패널로 재배치해 2단 레이아웃으로 바꾼다.
- 팔레트 배치: 스와치를 `display: grid`로 4~6열 격자에 배치, 각 스와치는 정사각형 버튼(최소 44px)이며
  둥근 모서리를 준다. 선택된 스와치는 테두리 강조 + 작은 체크 아이콘으로 표시(색만으로 구분하지 않음 —
  6장 참고). 커스텀 색상 picker는 팔레트 그리드 옆(또는 아래)에 "커스텀" 스와치 형태의 트리거로 둔다.
- 색상 목록(프리셋, 예시 — 최종 값은 구현 시 대비율 확인 후 확정): 검정, 흰색, 회색(밝음/중간/어두움),
  빨강, 주황, 노랑, 연두/초록, 청록, 파랑, 남색, 보라, 분홍 등 12~16색.
- 격자 크기/스케일: 논리적 격자는 항상 16x16 고정. 화면 표시 배율은 반응형으로 변하되(모바일에서
  캔버스 CSS 폭이 줄어듦), 내부 렌더링 해상도(512x512, 셀당 32px)는 고정해 그리기 정밀도를 유지한다.
- 애니메이션: 기본적으로 최소화한다. 스와치 선택 시 테두리 강조는 즉시 적용하거나 150ms 이내의 짧은
  `transition`만 사용한다. 캔버스 자체에는 애니메이션을 넣지 않는다(그리기 반응성을 최우선).

## 5. 마우스/터치 조작 방식 상세

- **마우스**: 캔버스 위에서 `pointerdown`(좌클릭)으로 첫 칸을 칠하고, 버튼을 누른 채 이동하면
  `pointermove`가 지나는 칸을 연속으로 칠한다(같은 칸에서 중복 호출은 무시). 버튼을 떼면(`pointerup`)
  스트로크가 끝나고 undo 스냅샷이 확정된다. 캔버스 바깥으로 나갔다가 버튼을 뗀 경우에도
  `setPointerCapture` 덕분에 `pointerup`을 정상적으로 받는다.
- **터치(모바일)**: 손가락으로 캔버스를 터치하면 `pointerdown`, 누른 채 이동하면 `pointermove`가
  동일하게 발생해 마우스와 같은 코드 경로를 탄다. 캔버스에는 `touch-action: none`을 지정해 손가락으로
  그림을 그리는 동안 페이지가 스크롤되지 않게 한다.
- **지우개**: 지우개 버튼을 눌러 모드를 켠 상태에서 위와 동일한 클릭/드래그 동작을 하면, 칠하는 대신
  해당 칸을 `null`(투명)로 되돌린다. 지우개 모드는 다른 색상 스와치를 선택하면 자동 해제된다.
- **전체 지우기**: 버튼 클릭 시 `confirm()` 수준의 간단한 확인(또는 짧은 "정말 지울까요?" 확인 UI) 후
  격자 전체를 빈 칸으로 리셋하고, 이 동작도 undo 스택에 스냅샷으로 남겨 실수로 전체 지우기를 눌러도
  되돌릴 수 있게 한다.
- **실행 취소(undo)**: 툴바의 "되돌리기" 버튼 클릭, 또는 키보드 단축키(`Ctrl+Z` / macOS `Cmd+Z`)로
  가장 최근 스트로크(또는 전체 지우기) 이전 상태로 복원한다. 스택 깊이는 예를 들어 최근 30~50단계로
  제한해 메모리를 과도하게 쓰지 않게 한다. 스택이 비어 있으면 undo 버튼을 비활성화(`disabled`)한다.
- **PNG 저장**: "PNG로 저장" 버튼을 클릭하면 3장의 내보내기 로직에 따라 파일 다운로드가 즉시 시작된다.
  별도의 확인 절차는 없다(되돌릴 수 없는 파괴적 동작이 아니므로).

## 6. 접근성 고려사항

그림을 캔버스에 직접 찍는 행위 자체는 본질적으로 시각적인 작업이라, 스크린리더 사용자가 그림을
"보면서" 그리는 것을 완전히 대체할 방법은 없다는 한계를 인정한다. 다만 그 한계 밖의 요소(도구 선택,
상태 안내, 대비, 포커스, 터치 타깃)는 최대한 접근 가능하게 만든다.

- **팔레트의 키보드 접근성**: 모든 색상 스와치와 지우개/전체 지우기/undo/저장 버튼을 `<button>`
  요소로 구현해 기본적으로 `Tab` 포커스 이동과 `Enter`/`Space` 실행이 가능하게 한다. 각 스와치에는
  `aria-label="색상: 빨강"`처럼 색상 hex 값이 아닌 사람이 읽을 수 있는 이름을 붙이고, 현재 선택된
  스와치/지우개 버튼에는 `aria-pressed="true"`를 부여해 스크린리더가 "선택됨" 상태를 읽어주게 한다.
  모든 상호작용 요소에 `:focus-visible` 윤곽선 스타일을 CSS로 명시한다.
- **색약자 대응**: 선택 상태를 색상 변화(테두리 색 등) 하나에만 의존하지 않고, 테두리 두께 변화 +
  체크 아이콘(또는 `✓` 문자/아이콘) 같은 형태 요소를 함께 사용해 "색이 아니라 형태로도" 선택 여부를
  구분할 수 있게 한다. 프리셋 색상 팔레트는 밝기(명도)가 서로 다른 색을 고르게 섞어, 색상만으로 구분이
  어려운 경우에도 명도 차이로 어느 정도 구분되게 구성한다. UI 자체(버튼, 텍스트, 배경)는 팔레트
  스와치를 제외하고 WCAG AA(4.5:1) 대비를 지킨다.
- **캔버스 그리기의 대안(가능한 범위)**: 캔버스에 `tabindex="0"`과 `role="application"` 또는
  `aria-label="16x16 픽셀 그림판"`을 부여해 포커스는 가능하게 하되, 픽셀 단위 키보드 그리기(방향키로
  커서 칸 이동 + `Enter`/`Space`로 칠하기, `Delete`로 지우기)는 **선택적 향후 개선 과제**로 남긴다
  (이번 계획의 필수 범위는 아니다 — 마우스/터치가 기본 입력 방식이라는 전제 위에서, 시간이 허락하면
  Build 단계에서 최소 구현을 시도해볼 수 있음을 명시해 둔다).
- **상태 변화 안내(스크린리더)**: 화면에 보이지 않는 `aria-live="polite"` 영역을 하나 두어, "전체
  지우기 완료", "되돌리기 완료", "PNG 파일로 저장되었습니다" 같은 동작 결과를 텍스트로 알린다. 다만
  칸 하나하나를 칠할 때마다 알리지는 않는다(너무 잦은 알림은 오히려 방해가 되므로, 의미 있는 단위의
  동작에만 알림을 건다).
- **모션 최소화**: `prefers-reduced-motion: reduce`를 존중해 스와치 선택 시의 짧은 transition조차
  비활성화한다(원래도 애니메이션이 거의 없는 앱이라 영향은 작다).
- **터치 타깃 크기**: 팔레트 스와치, 지우개/전체 지우기/undo/저장 버튼 모두 최소 44px 높이·너비를
  확보한다.
- **이미지/아이콘**: 체크 아이콘, 지우개 아이콘 등 장식적 성격의 아이콘은 `aria-hidden="true"`로
  처리하고, 버튼의 의미는 텍스트 라벨(또는 `aria-label`)로 전달해 아이콘 유무와 무관하게 이해 가능하게
  한다.
