# 픽셀 아트 에디터 — 추가 Review 결과

> 기존 review.md와 HTML/CSS/JS를 대조한 독립적인 코드 레벨 검토다.
> 기존에 언급된 캔버스 기본 포커스·키보드 그리기·좌표 클램프 등은 반복하지 않았다.
> 실제 브라우저 검증은 수행하지 않았으며, 레이아웃 문제는 CSS 치수 계산을 근거로 기록했다.

## 1. 모바일 대응

- **320px 화면과 2단 전환 직후의 폭에서 가로 넘침 발생 조건이 있음**
  - 위치: `style.css:120–131` — 팔레트 격자, `style.css:248–269` — 2단 레이아웃.
  - 팔레트는 최소 44px인 스와치 6개와 8px 간격 5개로 내부 폭 304px이 필요하다. 패널의 좌우 패딩·테두리를 합치면 최소 330px이다.
  - 320px 화면은 body 패딩을 제외하면 288px만 남으므로 팔레트가 공간을 초과한다.
  - 720px부터는 축소되지 않는 512px 캔버스와 20px 간격, 최소 330px 팔레트가 나란히 놓인다. 필요한 본문 폭은 862px인데 720px 화면의 가용 폭은 688px이다. 기존 375px·900px 검증 사이에 빠진 구간이다.
  - 좁은 화면에서는 팔레트 열 수를 줄이고, 2단 전환 시점은 두 패널이 실제로 들어갈 수 있는 폭에 맞춰야 한다.

- **두 손가락 입력이 하나의 스트로크 상태를 덮어씀**
  - 위치: `pointer.js:55–91`, `editor.js:123–134`.
  - 활성 pointerId를 저장하거나 다른 포인터를 거르는 조건이 없다. 두 번째 pointerdown도 스트로크 시작을 호출해 첫 번째 입력의 스냅샷과 마지막 좌표를 초기화한다.
  - 이후 서로 다른 손가락의 이동이 하나의 lastCell로 연결되어 의도하지 않은 선이 생길 수 있다. 어느 손가락이든 먼저 떼면 전체 drawing 상태가 종료된다.
  - 첫 번째 입력의 시작 스냅샷도 덮어써져 되돌리기 범위가 달라진다. 한 포인터만 활성 스트로크를 소유하도록 제한할 필요가 있다.

## 2. 엣지 케이스 및 상태 관리

- **그리는 도중 Ctrl/Cmd+Z를 누르면 되돌리기 이력이 뒤섞임**
  - 위치: `editor.js:123–134` — 스트로크 스냅샷, `editor.js:148–165` — 되돌리기·단축키.
  - 진행 중인 스트로크의 스냅샷은 포인터를 뗄 때 저장되지만, 단축키는 그 전에도 이전 undo 항목을 즉시 적용한다.
  - 예를 들어 A를 그린 뒤 B를 그리는 중 Ctrl+Z를 누르면 빈 그림으로 돌아간다. 이후 포인터를 떼면 B 시작 전 상태인 A가 스택에 추가되어, 다음 되돌리기가 A를 다시 나타나게 한다.
  - 활성 스트로크와 undo를 조정하는 처리가 필요하다. 스트로크를 확정한 뒤 되돌리거나, 진행 중인 스트로크 자체를 취소하는 정책으로 일관성을 유지할 수 있다.

- **PNG 생성 결과를 확인하기 전에 저장 완료를 안내함**
  - 위치: `editor.js:156–158` — `handleSave()`, `canvas.js:49–61` — `exportGridAsPng()`.
  - 비동기 toBlob 콜백이 끝나기 전에 'PNG 파일로 저장되었습니다'를 안내한다. 콜백이 null을 받는 실패 경로에서는 다운로드 없이 반환하지만 성공 안내는 이미 표시된다.
  - 내보내기 함수가 생성 성공·실패를 반환하도록 하고, 확인 가능한 단계에 맞춰 안내해야 한다. 다운로드 요청과 실제 파일 저장 완료도 구분할 필요가 있다.

## 3. 성능

- **보간된 셀마다 전체 캔버스를 다시 그림**
  - 위치: `pointer.js:60–62` — `paintTo()`, `editor.js:114–120` — `paintCell()`, `canvas.js:18–29`.
  - 하나의 pointermove가 여러 셀을 보간하면 변경된 셀마다 render()가 호출된다. 각 호출은 전체 캔버스를 지우고 256칸을 순회한다.
  - 첫 칸을 칠한 상태에서 같은 행의 마지막 칸까지 한 번에 이동하면, 나머지 15칸 변경에 대해 전체 렌더링이 15회 실행될 수 있다.
  - 현재 크기에서 체감 지연은 측정하지 않았으나 중복 작업은 코드로 확인된다. 셀 상태 변경을 묶고 이벤트당 또는 애니메이션 프레임당 한 번 렌더링하는 방식이 적절하다.

## 4. 수정 여부

다섯 가지 지적 모두 타당하다고 판단해 반영했다 (`pointer.js`, `editor.js`, `canvas.js`, `style.css`).

- 320px/720px 부근 가로 넘침 → `.swatch-grid`를 고정 `repeat(6, 1fr)`에서 `repeat(auto-fit, minmax(44px, 1fr))`로 변경해 좁은 폭에서 열 수가 자동으로 줄어들게 함.
- 두 손가락 입력이 하나의 스트로크 상태를 덮어씀 → `activePointerId`를 저장해, 이미 그리는 중이면 다른 포인터의 down/move/up을 무시하도록 수정.
- 그리는 도중 Ctrl/Cmd+Z로 되돌리기 이력이 뒤섞임 → `handleUndo()`에서 활성 스트로크(`strokeSnapshot`)가 있으면 되돌리기를 무시하도록 가드 추가.
- PNG 저장 완료 안내가 실제 생성 전에 표시됨 → `exportGridAsPng()`가 `onComplete(success)` 콜백을 받도록 바꾸고, `handleSave()`가 그 결과에 따라 성공/실패 메시지를 다르게 알리도록 수정.
- 보간된 셀마다 전체 캔버스를 다시 그림 → `paintCell()`이 즉시 `render()`를 호출하지 않고 `requestAnimationFrame`으로 한 프레임당 한 번만 다시 그리도록 배치 처리.
